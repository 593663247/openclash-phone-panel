# 设备绑定持久化（1.2.0）

## 安装后首次迁移

升级包只更新程序，不会根据不明旧记录自动重建绑定。

1. 先创建一份本地完整备份，保留本地管理连接。
2. 进入“管理维护 → 设备绑定持久化 → 预览迁移 / 检查”。
3. 核对每台设备的名称、固定 MAC、固定 IP、当前租约、目标节点以及 DHCP 名称差异。源配置中已有的手机前缀 `/32` 规则也会列入核对；损坏或矛盾记录不会当成空列表处理。
4. 确认后点击“确认保存并应用”。任务先备份，再保存独立记录、生成并校验配置、重载和验收。
5. 等待“运行态已验收”；改过 IP 的手机需要重新连接 Wi-Fi，实际出口与 UDP 另行检测。

在迁移完成之前，已有设备的修改/继续添加会要求先迁移。全新空配置首次从面板添加设备时，可以直接建立独立绑定库。

## 保存的数据

- `/etc/phone-dns/managed-bindings.yaml`：格式版本、修订号、以固定 MAC 生成的稳定设备标识、名称、固定 IP、目标节点、DHCP 名称和精确规则所有权历史。
- `/etc/phone-dns/managed-nodes.yaml`：面板托管节点的真实参数及认证，旧格式保持兼容，但损坏数据不会被忽略。
- `mapping.yaml`、`devices.yaml`、监听、DNS 与防火墙配置：从独立记录派生。分组数字 ID 可以变化，设备仍按节点名称绑定。
- `persistent-guard.yaml`：上次成功加载的独立防直连保护数据，仅包含网桥与 IP/MAC，绑定库损坏时可在启动阶段继续保护。
- `state/persistence-status.yaml`、`state/bindings-last-good.yaml`：生成/验收/阻止/中断状态，以及上次完整验收快照。

使用面板修改数据，不建议手工编辑独立文件。格式版本不受支持、记录损坏或已迁移记录意外丢失时会停止合并，保留恢复入口，不自动清空数据或猜测设备身份。手机应使用稳定 Wi-Fi MAC；更换 MAC 需要明确处理设备身份。

## 订阅更新与切换配置

须保留并启用 OpenClash 中安装的自定义覆盖与防火墙钩子。配置加载前，面板将独立节点和绑定合并到当前源 YAML 与生成的运行 YAML，再生成 DNS、监听和保护规则。

规则所有权按历史上明确接管/写出的完整 `SRC-IP-CIDR,IP/32,节点` 字符串记录。改绑、改 IP 和删除只替换或清理这些已知精确规则；域名规则、其他 IP、其他 CIDR 和其他目标不会被批量删除。已解除的旧绑定不会因切回旧配置自动复活。同 IP 的非面板规则、重复规则及同名不同参数的托管节点会阻止应用，不能自动改绑或转为 DIRECT。

未由面板托管的订阅节点仍由订阅提供参数：持久化保持节点名称绑定，不保证第三方服务的公网出口永不变化。面板托管落地节点的参数冲突则会明确报错。

## 冲突处理

- 缺少目标节点：恢复正确节点、选择兼容配置，或恢复上次验收快照。
- 静态 IP/MAC 重复、MAC 不符、DHCP 名称不符：先核对 DHCP 或通过面板明确修改，不能直接覆盖其他租约。
- 动态租约或邻居表显示目标 IP 属于其他 MAC：先释放地址冲突；不会自动清理别人的租约或邻居。
- 同一设备仍持有旧租约：显示等待重连；不得将配置已保存当成手机已换址。
- 格式版本未知、独立文件损坏/丢失：优先恢复完整快照，不退回旧导入模式。

## 保护、重启与中断

独立 nft 表 `inet phone_panel_persistent` 在代理加载前保护已登记设备的 IPv4 地址和所有地址族的固定 MAC 转发；它不通过 INPUT 链拦截本机代理接收。替换 fw4 表不会移除此表。启动辅助服务在早期加载记录；新装未迁移时不会自动接管设备网络。

用户写入采用临时文件、文件同步、原子替换及目录同步。后台变更不会在重启后自动重放；已保存意图的派生配置可以重新生成。进程/启动标识用于识别中断。配置加载与面板应用共享锁，避免两个写入方互相覆盖。

独立表仍依赖内核 nft 支持、正常的启动服务、网桥设置和稳定 MAC；手工清空全部 nft 规则、破坏启动文件或存储硬件损坏不属于可证明的自动恢复保证。

## 完整备份与恢复

成功验收后保存包含源/运行配置、配置选择、面板设置、节点库、绑定库、DHCP 和派生文件的私密快照。清单带 SHA256 完整性校验；上次验收及仍被恢复任务引用的快照不能回收。

“恢复上次验收配置”会先备份当前状态，再恢复完整快照和配置选择，重载后重新验收；不是只撤销某台手机。失败时分别报告文件与运行态恢复结果。旧的、不包含独立绑定格式的备份不能覆盖已迁移状态；程序回退也拒绝早于该格式/启动保护的版本。

快照包含节点凭据及订阅配置，仅保存在路由器私密目录，不提交 GitHub。恢复后仍需核对手机租约与实际出口。

## 已覆盖的自动化检查

包含迁移只读与过期预览、节点/租约冲突、稳定身份、规则所有权、订阅覆盖与源/运行配置重建、跨配置完整恢复、故障注入、丢失/损坏状态、进程中断、强制终止写入、并发锁、真实隔离 nft 表和实际 sing-box 配置检查。前端包含迁移预览、防重复提交及桌面/手机浏览器检查。

这些检查不替代真实路由器的订阅钩子、重启、物理断电恢复、跨固件或全部网络业务验收。
