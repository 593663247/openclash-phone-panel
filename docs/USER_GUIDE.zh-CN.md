# 中文使用手册

## 1. 登录与界面

登录现有 LuCI 后进入 **服务 → 手机出口与 DNS**。不需要新的公网端口或单独账号。不要将管理页面或控制 API 暴露到公网。面板需要管理员权限，安装时必须保留原 LuCI 登录与 CSRF 检查。

- **DNS 入口监听**：进程端口存在，不等于上游连通。
- **防直连规则已加载**：检测到保护链，不是完整泄漏测试。
- **已有租约**：租约记录存在，不证明设备在线。
- **节点 UDP 配置**：读取 `udp: true`，不证明 UDP ASSOCIATE 成功。
- **活动连接 / UDP**：内核连接记录数量，不是请求成功率。
- **检测 DNS / 出口**：查询 example.com；通过固定 SOCKS 访问 api.ipify.org。会向外部服务发出请求。不会模拟手机所有业务。

面板每15秒刷新读状态；不会每15秒重写网络配置。

## 2. 自动导入（以源配置为准）

1. 在活动源配置中添加真实代理项，名称以 `手机-` 开头。
2. 在 `rules` 顶部添加唯一规则：

   ```yaml
   - SRC-IP-CIDR,192.168.1.101/32,手机-01-示例
   ```

3. 在 DHCP 中为该 IP/MAC 建立唯一静态租约；也可以使用未过期的唯一当前租约，导入器会尝试生成静态租约。
4. 保存并应用 OpenClash。应用会短暂中断代理服务。
5. 刷新面板，核对设备所属节点与独立DNS。待处理项会显示原因。

不同手机可共用一个节点，共用其 DNS 缓存/解析出口；分组隔离按节点，不是按手机进程。DNS 上游为 Google `8.8.8.8`/`8.8.4.4`，通过 HTTPS/TLS `dns.google`，出口固定到该节点，不退回运营商 DNS。

自动开启 UDP 只作用于 `手机-` SOCKS5 业务代理。新节点本身仍须真正支持 UDP。DNS-only 本地 SOCKS 的 `udp:false` 不影响业务代理 UDP。

## 3. 手动添加设备

填写名称、固定 Wi-Fi MAC、空闲 IP、节点 → **检查并预览** → 核对 → **确认应用**。任务会检查冲突、保存恢复记录、更新静态租约/来源规则/DNS/保护，校验后重启相关服务。手机重新连接 Wi-Fi 后手动检测对应组。

使用手机连接此 Wi-Fi 时的实际 MAC；关闭“定期轮换”的随机MAC或设置为稳定模式。不要输入另一网络的MAC或把离线静态设备的IP分给新手机。

如果已有同一IP、同一节点的唯一来源规则，手动添加可用于补齐自动导入缺失的MAC。冲突时先人工修复，不要盲目选择其他节点。

## 4. 改绑、删除与限制

改绑：在活动源配置修改已有 `/32` 规则目标，保存并应用；受管设备的DNS会跟随业务节点，不反向修改业务节点。

不会自动删除旧设备，也没有通用删除按钮。删除来源规则、删除节点或重命名前先迁移设备并人工检查 mapping、租约、监听、nft集合。找不到唯一有效规则时会拒绝对齐，避免猜测。

支持单个可配置 LAN 内的 IPv4 `/32` 单机来源规则（LAN CIDR 参数允许 /8～/30，默认 /24）；代理组、任意CIDR、IPv6源地址和多LAN需要开发适配。不自动更新订阅内容，也不提供节点服务。

## 5. 排错

| 现象 | 检查 |
|---|---|
| 节点缺失 | 是否为活动源配置中的独立代理、名称是否以 `手机-` 开头 |
| 待补MAC | 手机联网并确认DHCP租约，或补唯一静态租约后重新应用 |
| DHCP冲突 | 检查同IP多MAC、同MAC多IP及未保存的UCI修改 |
| 导入失败 | `/32` 来源规则必须唯一并位于其他类型规则之前 |
| 页面仍是旧版本 | 完整刷新LuCI；修改源码后确认模板缓存已更新 |
| 入口监听但检测失败 | 检查上游凭据、SOCKS连通、链式拨号与DoH端点 |
| UDP已开启但应用异常 | 实测服务端UDP ASSOCIATE、relay端点、TPROXY、策略路由及回程 |
| context deadline exceeded | 超时不是唯一原因判据，结合连接目标、节点日志及实际探测定位 |
| rejected username/password | 先核对节点服务端认证，勿将凭据贴进Issue |
| 应用后断网 | 使用本地恢复连接，按INSTALL中的恢复步骤核对运行态 |

## 6. 安全与恢复

所有写操作需要LuCI登录和POST CSRF token；不要移除这些检查。此实现运行权限高，不应给不可信账号面板访问权。

快照包含敏感DHCP、代理配置，保存在路由器本地；不要公开上传。自动恢复不是事务系统：并发改配置、服务启动失败、断电、进程崩溃可能留下运行态不一致。必须保留有线/本地恢复通道。

MAC保护可能阻断外部IPv6；本地私网目的地址在参考路由中保留直达，不能声称“每一包都走代理”。客户端私人DNS/应用DoH不受普通53端口接管；需单独测试。配置就绪、出口探测成功并不等于无DNS/IPv6泄漏。

## 7. 状态与任务恢复

编辑表单或节点列表变化后，旧预览失效，需重新检查。节点或设备绑定变化时旧链路检测结果会清除。控制 API 不可读时显示“无法读取”，不解释为零连接；状态读取超过 15 秒会释放刷新按钮。

应用任务 ID 保存在当前标签页的会话存储中；刷新后可继续查询。等待约五分钟仍未结束时，点击“继续查询上次任务”。在任务明确结束前不能重复添加设备。禁用浏览器会话存储时无法跨刷新恢复，请保存页面显示的任务 ID。日志面板仅展示时间、受管 IP 和错误分类，详细日志需在路由器本地查看。
